# Speckit 规范驱动开发工作流

## 核心理念

规范驱动开发是一套结构化流程，其核心强调：

- **意图驱动开发**：先由规范定义 "做什么"，再确定 "怎么做"
- **创建完善的规范**：借助约束规则与组织原则形成完备规范
- **多阶段逐步精化**：而非仅通过提示词一次性生成代码
- **深度依托先进 AI 模型能力**：完成规范的理解与解析

## 流程步骤

1. `specify init`
2. 执行命令

## 核心命令

| 命令 | 中文说明 |
|------|----------|
| `/speckit.constitution` | 创建或更新项目治理原则与开发规范 |
| `/speckit.specify` | 定义你要构建的内容（需求 + 用户故事） |
| `/speckit.plan` | 根据选定技术栈创建技术实施方案 |
| `/speckit.tasks` | 生成可执行的实现任务清单 |
| `/speckit.implement` | 按计划执行所有任务，完成功能开发 |

## 可选命令（用于质量提升与验证）

| 命令 | 中文说明 |
|------|----------|
| `/speckit.clarify` | 澄清定义不明确的部分（建议在 `/speckit.plan` 前使用；原名为 `/quizme`） |
| `/speckit.analyze` | 跨产物一致性 & 覆盖率分析（在 `/speckit.tasks` 之后、`/speckit.implement` 之前运行） |
| `/speckit.checklist` | 生成自定义质量检查清单，验证需求的完整性、清晰性与一致性（如同 "自然语言的单元测试"） |
